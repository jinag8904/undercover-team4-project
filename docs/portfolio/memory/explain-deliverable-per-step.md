작업(단계)을 시작할 때, 그 작업을 하면 **어떤 것이 만들어지는지(산출물/결과)** 를 이해하기 쉽게 + 간략히 먼저 설명한 뒤 들어간다.

**Why:** 사용자는 코드 편집을 직접 하고([[edits-by-user]]) 이해 지향([[user-profile]])이라, 단계별로 "이걸 하면 뭐가 생기는지"를 알아야 판단·작업할 수 있다.

**How to apply:** 각 단계 앞에 "[산출물]: ~~가 생긴다" 식 한두 줄 요약을 붙인다. 장황한 옵션 나열 대신 결과물 중심으로. #222 계획 문서(docs/issue-222-faction-symbol-plan.md)가 이 형식의 예시.
