## 1. NPC 외형 적용 — 확정 설명

핵심 파일
- `Assets/Scripts/NPC/Appearance/AppearanceAssigner.cs` — 배정 규칙 (서버 권위)
- `Assets/Scripts/NPC/Appearance/NpcAppearance.cs` — 실제 시각 적용 + 네트워크 동기화
- `Assets/Scripts/Data/Appearance/AppearanceProfile.cs` — 축 enum, 프로필 구조체, 공개 축 비트마스크
- `Assets/Scripts/Data/Appearance/AppearanceDatabase.cs` — 축별 옵션(이름·프리팹·색) 정의 SO

### 구현 방법 (슬라이드용 요약)

1. **외형 = 6축 인덱스 6개**
   `AppearanceProfile`은 머리스타일/머리색/피부색/수염/모자/안경 축의 **옵션 인덱스만** 가진 struct.
   메시·색 같은 실물은 `AppearanceDatabase`(SO)가 인덱스별로 들고 있다.
   → 네트워크로는 int 6개만 오가고, 각 피어가 같은 DB에서 같은 리소스를 찾아 그린다.

2. **배정은 서버 권위, 적용은 각 피어**
   서버의 `AppearanceAssigner`가 프로필을 정해 `NpcAppearance.SetProfile()` 호출 →
   `NetworkVariable<AppearanceProfile>`에 대입 → 각 클라의 `OnValueChanged`에서 `ApplyProfile()`.
   외형으로 범인을 대조하는 게임이라 **전원이 같은 외형을 봐야 하는 것**이 이 구조의 이유.
   늦게 들어온 클라도 스폰 페이로드에 값이 실려 와 그대로 적용된다.

3. **적용 방식 — 에셋 팩마다 경로가 둘이다**

   | | Generic 경로 (`NpcAppearance`) | SciFi 경로 (`NpcCatalogAppearance`) |
   |---|---|---|
   | 에셋 | Synty Generic 바디 13종 | 통짜 SciFi 바디 20종 |
   | 만드는 법 | 바디 토글 + 축별 프롭 부착 + 틴트 | **바디 토글만** (프롭 부착 없음 — 바디가 외형 100% 전담) |
   | 방향 | 프로필 → 외형 (**조립**) | 모델 → 프로필 (**룩업**, `AppearanceModelCatalog`에 조합이 고정 값으로 박힘) |
   | 동기화 | `NetworkVariable<AppearanceProfile>` (int 6개) | `NetworkVariable<int>` (모델 인덱스 1개) |

   공통 기법
   - 바디: SkinnedMeshRenderer 변형 중 하나만 `SetActive` — 같은 스켈레톤 바인딩이라 본 유지(메시 교체 불필요)
   - 프롭(Generic만): 머리 본 앵커에 `Instantiate` 후 부착
   - 색(Generic만): `MaterialPropertyBlock`으로 렌더러별 틴트 → **공유 머티리얼 불변**(인스턴스 누수 없음)

4. **"랜덤"이 아니라 역할별 배정** ← 이 슬라이드의 진짜 알맹이
   범인 확정(`CriminalAssigner.OnCriminalAssigned`) 후 전 NPC를 세 역할로 나눠 배정한다.
   - **범인**: 프로필 확정 → 그중 공개할 축을 k개(기본 2) 뽑음 = 몽타주
   - **디코이**: 담당 범인의 *공개 축만* 복사, 나머지 축은 랜덤 → 몽타주에 걸리는 사람이 범인 포함 k명(기본 3)
   - **나머지**: 모든 범인과 공개 축이 최소 1개는 다르게 (`CreateNonMatchingProfile`, 실패 시 최대 16회 재추첨)
   → 몽타주 부합 인원 k가 곧 **난이도 노브**. 무작위로 뿌리면 "몽타주에 걸리는 사람이 0명 또는 10명"이 되어 게임이 성립하지 않는다.

   같은 규칙이 경로에 따라 **생성 vs 탐색**으로 갈린다:
   - Generic — 조합을 자유롭게 만들 수 있으니 **만든다** (`CreateDecoyProfile`, `CreateNonMatchingProfile`)
   - SciFi — 조합이 카탈로그 20종으로 고정이라 조건 맞는 모델을 **찾는다** (`FindModelMatchingRevealed`, `PickNonMatchingModel`).
     못 찾으면 부합 인원 k가 미달할 수 있어 경고를 남긴다 — Generic엔 없는 실패 모드.
   - SciFi 전용 제약: `NonHumanoid`(에일리언 등)는 그림 몽타주의 인간 두상으로 안 읽혀 범인·디코이에서 제외, 일반 시민으로만 등장 (`CanDepict`)

5. **공개 축은 범인마다 따로 뽑는다**
   대머리면 머리색을 말할 수 없고(#556), 포트레이트로 그릴 수 없는 값도 못 쓴다(#607).
   전 범인 공통으로 두면 그 제약이 전부 합쳐져 몽타주가 빈약해지므로, 범인별로 뽑아 `RevealedAxisSet`(1바이트 비트마스크)에 담는다.

6. **서버만 아는 정답 vs 클라에 보낼 것**
   `AppearanceProfile.Masked(공개축)` — 공개되지 않은 축은 화면에서 숨기는 게 아니라 **애초에 전송하지 않는다**(-1로 지운 사본을 보냄). 패킷을 뜯어봐도 정답이 안 나온다.

### 말할 거리 (면접/발표용)
- "왜 문자열이 아니라 인덱스인가" → 대역폭 + 다국어(문장 조립은 표시하는 쪽이 자기 언어로, #497)
- "왜 디코이를 심었나" → 난이도를 확률이 아니라 **수(k)로 통제**하기 위해
- "경로가 둘인데 규칙은 하나" → 프롭 조립(Generic) / 통짜 모델(SciFi)로 만드는 법은 달라도 "몽타주 부합 k명" 보장은 동일. 한쪽은 조합을 만들고, 다른 쪽은 카탈로그에서 찾아서 같은 결과를 낸다
- "왜 마스킹해서 보내나" → 서버 권위 + 치팅 방지

### 18 몽타주 트러블슈팅 — 제목 `몽타주 — 모르는 축`  (문제→해결→결과 형식, 슬라이드 11과 같은 틀)
- **문제**: 범인 외형 6축 중 일부만 공개되는 구조라, 몽타주에서 "모르는 축"을 어떻게 보여줄지가 문제였다. 머리 스타일을 안 그리면 대머리와 '모른다'가 구분되지 않는다.
- **해결**: 코드로 예외를 더 처리하는 대신 **공개 축 개수를 인스펙터 값으로 두고 최대로 올려 미상 자체를 없앴다**. 미상 표현 코드는 지우지 않아 값만 내리면 예전 규칙이 되살아난다 (Cyberpunk 전부 공개 / Apocalypse 한 축 미상).
- **결과**: 몽타주가 설명 없이 그림 한 장으로 읽힌다. 난이도는 코드가 아니라 공개 축 수로 조절.
- **그림**: `montage_trouble.png` (시도 ①~④ 시퀀스, 전부 '머리 스타일 미상' 케이스로 통일) 한 장만. 지금 슬라이드의 **아래 상자 4개 줄은 삭제** — 시퀀스 캡션이 같은 내용.

### 19 상점 카탈로그 — 제목 `상점 카탈로그`
- 문장 3개:
  1. 판매 후보는 `ShopCatalog`(SO) 하나에 등록 — 아이템 추가가 씬 편집이 아니라 카탈로그 항목 추가가 되고, 카탈로그 인덱스가 곧 네트워크 계약(칸에는 인덱스만 실린다).
  2. 진열·주문·품절·자금 판정은 전부 서버 한 곳(`ShopLineup`) — 클라는 칸 번호만 보내고 결과를 `NetworkList`로 받는다. 두 사람이 같은 칸을 동시에 눌러도 서버가 순서대로 처리해 한 명만 산다.
  3. 구매 직후 세이브를 갱신한다(#925) — 상점에서 사고 나갔다 이어해도 산 칸이 다시 열리지 않는다.
- **그림**: `shop_a_roll.png`(1800×540) 위, `shop_b_order.png`(1800×460) 아래로 **세로 2단**. 겹치지 말고 같은 폭으로. 왼쪽 상점 스크린샷은 빼거나 작게 구석에.

### 21 미니맵 — 제목 `미니맵`
- 문장 3개 (현재 본문 문단 5줄 → 제목 옆으로 압축):
  1. 맵이 덮는 월드 사각형(중심·크기)을 `MinimapArea` 한 곳에 두고, 본부 콘솔·휴대용 미니맵·항공뷰 굽기가 전부 그 값을 읽는다 — 배경 그림과 아이콘 좌표가 어긋날 수 없다.
  2. 미니맵은 표시 대상 목록을 갖지 않는다. `MinimapTarget`을 붙인 오브젝트가 켜질 때 스스로 등록하고 꺼질 때 빠지므로, 새 대상은 컴포넌트만 붙이면 되고 아이콘 옵션도 그 컴포넌트 값이다.
  3. 전자기기 먹통 이벤트 중에는 지도를 판으로 덮어 가린다(#762) — 렌더를 끄는 게 아니라 가리기만 해서, 풀리는 순간 최신 상태가 바로 보인다.
- **그림**: `minimap_scene.png`(1800×600) 본문 전체 폭 + 오른쪽에 인게임 스크린샷(지금 것 재사용). 본문 문단은 삭제.
